The library expansion question, and context that survives a session gap

No scheduled milestone — a planning change driven by your comment on the schedule board, plus the context-file work. Day 1 is still the next build.

What moved

  • The schedule grew from 12 days to 13. Ingredient identity is now day 5, after the recipeDb split and before the library grows.
  • §8 of the plan works your comment through end to end, and the schedule board now answers it on the page rather than only in a thread.
  • VISION carries the directional half: an ingredient becomes an entity with an identity, and the plan should eventually know what things cost in a real shop.
  • CONTEXT.md now leads with the three board URLs and the comment loop, so a new session cannot miss the mechanism that steers the plan.

What I found that changed the answer

  • 501 recipes stand on only 182 curated ingredients — the ceiling is the ingredient table, not the recipe count.
  • A recipe references an ingredient as free text, with no id, so nothing can hang off an ingredient today — not a price, not a product, not an allergen flag.
  • No price or product layer exists, and approxCost never exceeds 3 — so budget: high behaves identically to medium. A control that encodes nothing.

What got in the way

  • Renumbering a schedule in two places is where an off-by-one hides. Done descending so numbers could not collide mid-rename, and verified by printing every id afterwards rather than trusting the replace.
  • A dangling cross-reference nearly shipped — the dimensions table pointed at “§8” before §8 existed. Caught by grepping the doc's own headers against its references.

How an entry is written

Six rules

01

One file per day. Never append to a shared file — two machines writing one file is a merge conflict, and a doc in this repo has already duplicated and diverged.

02

Write it the same day, as part of the day's definition of done. A log written from memory a week later is fiction.

03

Outcomes, not activity. “Explore's first-load JS fell 185 kB → N” beats “worked on bundling”.

04

Record what did not work, and why. It cannot be recovered from the code — a rejected approach leaves no trace there.

05

Every deferral names a destination and a reason.

06

Numbers get their source, so the next session can re-measure the same way.
