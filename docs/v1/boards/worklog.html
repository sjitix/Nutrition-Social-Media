What I found that the docs did not say

  • The crisis guard has no pre-scan. It fires only when the model routes to symptom_check, so a crisis message the model chooses to simply answer reaches the user in the model's own words. That blocks shipping a live model publicly.
  • The Kimi K3 clean re-run is gone — the grader only printed to stdout. Root cause fixed; the number still has to be re-measured.
  • src/lib exports 232 names; 68 are imported by nothing, and 35 more only by scripts/. primitives.ts alone exports 29 and uses 7.
  • ai.ts:runAssistant is dead code — no import anywhere.
  • No import cycles exist across all 27 modules, verified by depth-first search.
  • Two apps, not one. src/app/plan/page.tsx is 1,819 lines of a parallel product beside /sage.
  • Nothing in the UI writes a meal log, so Today infers “eaten” from the clock.

What got in the way

  • A heredoc ate the backslashes in the first analysis script, exactly as the standing note says it does. Cost one run. The lesson was already recorded and it recurred anyway — which is the argument for keeping it recorded.
  • My first “~60 unconsumed exports” figure was imprecise. Measured properly it is 68 or 103 depending on whether tooling counts as a consumer. Corrected before the commit landed rather than left as a soft number in a document that will be believed.

How an entry is written

Six rules

01

One file per day. Never append to a shared file — two machines writing one file is a merge conflict, and a doc in this repo has already duplicated and diverged.

02

Write it the same day, as part of the day's definition of done. A log written from memory a week later is fiction.

03

Outcomes, not activity. “Explore's first-load JS fell 185 kB → N” beats “worked on bundling”.

04

Record what did not work, and why. It cannot be recovered from the code — a rejected approach leaves no trace there.

05

Every deferral names a destination and a reason.

06

Numbers get their source, so the next session can re-measure the same way.
