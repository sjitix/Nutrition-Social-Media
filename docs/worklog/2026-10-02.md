## What I found that changed the answer

Checked before planning, and it reframed the ask:

- **501 recipes stand on only 182 curated ingredients.** The library's ceiling is the ingredient
  table, not the recipe count — a new recipe may only use an ingredient already curated to a real
  `fdcId`, because auto-matching produced `salmon fillet → Salmonberries`.
- **A recipe references an ingredient as free text** (`{name, quantity}`), with no id. So nothing can
  hang off an ingredient today — not a price, not a product, not an allergen flag.
- **There is no price or product layer at all**, and `approxCost` is a 1–3 integer that never exceeds
  3 — which means the `budget: high` setting currently behaves identically to `medium`. A user
  control that encodes nothing.

## What got in the way

- **Renumbering a schedule in two places is where an off-by-one hides.** The day rows live in a
  markdown table and in twelve HTML cards, and the decisions table references days by number. Done
  descending (D12→D13 first) so numbers never collide mid-rename, with the `id="D1"` quote included
  in the match so it could not also hit `id="D10"`. Verified by printing every id and decision cell
  afterwards rather than trusting the replace.
- **A dangling cross-reference nearly shipped.** The dimensions table pointed at "§8" before §8
  existed, which a reader would have hit as a dead end. Caught by grepping the doc's own section
  headers against its references.
