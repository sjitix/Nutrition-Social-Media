## What I found that the docs did not say

- **The crisis guard has no pre-scan.** It fires only when the model routes to `symptom_check`, so a
  crisis message the model chooses to simply *answer* reaches the user in the model's own words.
  That makes it a hard blocker on shipping a live model publicly, and it is now milestone C2.
- **The Kimi K3 clean re-run is gone** — not in `data/`, not in git, not in any temp directory. The
  grader only printed to stdout. Root cause fixed today; the number still has to be re-measured.
- **`src/lib` exports 232 names; 68 are imported by nothing at all**, and 35 more only by `scripts/`
  (correct — the harness must reach inside). `primitives.ts` alone exports 29 and 7 are used.
- **`ai.ts:runAssistant` is dead code** — no import anywhere in `src/` or `scripts/`.
- **No import cycles exist** across all 27 `src/lib` modules (verified by DFS). That is the starting
  point the layering gate should protect, not something it has to fix.
- **Two apps, not one.** `src/app/plan/page.tsx` is 1,819 lines of a parallel product beside
  `/sage`; only one of them can be V1. Scheduled as B2.
- **Nothing in the UI writes a meal log**, so Today infers "eaten" from the clock and the assistant
  can never reason about what actually happened. Scheduled as B1.

## What got in the way

  tool instead. The lesson is already recorded, and it recurred anyway — which is itself the
  argument for keeping it recorded.
- **My first "~60 unconsumed exports" figure was imprecise.** Measured properly it is 68 or 103
  depending on whether tooling counts as a consumer, and the two answer different questions.
  Corrected before the commit landed rather than left as a soft number in a document that will be
  believed later.
