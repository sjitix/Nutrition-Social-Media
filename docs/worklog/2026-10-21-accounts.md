# 2026-10-21 (accounts lane) — the Site URL batch: sign-out's scope, the fallback run for real, and a sentence for every cause

**Milestone:** the local live run of accounts. It covers two of the three items the README listed as
"not exercised, though this stack could do it", and fixes the sentences they showed to be wrong.
**Solved:** done, shipped as `c284616`, with its docs in the commit after. One item is left: a first link
with "Confirm email" on.

The batch began late on 2026-10-20, after `bbf0f17`. The first version and its first review ran
across midnight.

## What moved

- **Sign-out on one of two devices ends only that one.** Jo is signed in on the tablet since the
  takeover checks, signs in on the desk too, and signs out there. The desk's refresh token is refused;
  the tablet's still renews. That is `scope=local`; GoTrue's default (global) would end both.
- **The Site URL fallback, run for real.** Two new browsers stand for one browser at two web addresses:
  - a preview the allow list refuses ("Prev");
  - the Site URL's account page ("Site").
  Each has storage of its own, as a real browser keeps per address.
  - Kai asks on the preview, and the link lands on the Site URL's page. That page holds nothing, so the
    sign-in cannot finish, and the sentence names a different web address.
  - Asking again there brings the link back and signs Kai in.
  - Lee asks on the Site URL's page first and leaves it, then asks on the preview. That link lands
    where Lee's earlier request is still held, so GoTrue refuses the verifier (`bad_code_verifier`), and
    the takeover sentence must name the web address.
- **Each cause of the takeover sentence, shown against the real GoTrue:**
  - a different browser: Max asks on one browser, and the link is opened on the desk, which holds
    Ivy's request (new);
  - a different web address: Lee;
  - a newer request: Ivy.
- **Two sentences fixed in the app.** Before, both blamed another browser for what was really another
  address of the app:
  - the takeover sentence names the web address as a cause;
  - the no-request sentence names cleared browser data as well ("Delete everything in this browser"
    causes it).
- **A held request counts for 25 h, not 24.** GoTrue's default link life is a day, and a repeat request
  reuses the verifier for an hour without restamping it. So a link that still works can finish a
  request up to 25 h old, and at 24 h such a link got a sentence whose every cause was false. A fake
  test pins both edges (24.5 h finishes, 26 h does not).
- **The mutation runner, made to measure rather than predict:**
  - the allow-list mutation requires all nine landings;
  - the dropped-verifier mutation requires the tablet finishing Jo's link;
  - a new `passes` field requires Kai's second link to come back under a bare-domain Site URL, which
    only GoTrue's same-origin rule can do;
  - five new mutations: sign-out's scope, a bare-domain Site URL, the no-request sentence, and the
    takeover sentence's web-address and browser causes.
  Result: 22 mutations, 31 of the 45 checks shown able to fail, 22/22.

## What got in the way

- **The first review (8 agents, 21 findings, 20 confirmed) found the batch's own claims too strong:**
  - the runner said the eight later landings were "never reached once the first sign-in fails". The
    first sign-in does not fail under the allow-list mutation (the run hands each code to the device
    it names, and GoTrue's PKCE grant never reads the return address), so they had gone red,
    unrequired, all along;
  - "GoTrue admits the Site URL's own host" was credited to a check that cannot tell that rule from
    the fallback, which lands in the same place;
  - a global sign-out was said to stop the other device's sync "unsaid". In fact the device keeps
    syncing until its access token runs out, then says its sign-in expired;
  - the takeover sentence could be shown for the web-address case without naming it.
- **The re-review of those fixes** lost its verifiers to a session restart, so its 14 findings were
  verified by hand. Real:
  - K2 could not tell its branch from the takeover sentence, which now contains both phrases it
    asserted;
  - a "platform fact" (the tablet finishing Jo's link) turns red every time the dropped-verifier
    mutation runs;
  - "the live run shows all three causes" was true only for two, so Max's check was added;
  - the 24 h limit;
  - the wording: "every link lands back", "the device that asked", "all nine went red unrequired"
    (eight), "first two causes", and a 90 s figure the measured 80 s per run (1681 s for 21) did not
    support.
- **The restart also killed the full fake mutation run mid-mutation,** after 35 of 89: `supabase.ts`
  was left mutated. The runner's journal held the original, and it was put back, then checked byte for
  byte against a snapshot taken before the run. This is the recovery the journal exists for, used for
  real for the first time.
- **The engine gate, shared in turn with v1.**
  - v1's combined commit (C to G, `da023da`) held the gate for over an hour.
  - When it freed, this lane's mutation suites still had an hour to run, rewriting `src/lib/account` in
    place, so the slot went back to v1 for the shims removal (`5b6d874`).
  - Then the fake mutation run was stopped at 13 of 91 to free this lane's turn. Its journal put
    `client.ts` back, and a check that every anchor of both runners is present (113) and every
    distinctive replacement absent showed no mutation left applied.
  - The code shipped on main as of `1a816fd`, with the four new fake mutations run on their own first;
    the full fake run came after, and is in the gate below.
- **`ship` exited 4 after a real push.** v1's docs commit `6b9010b` touched `CLAUDE.md` under this
  lane's unshipped doc edits, so the folder could not catch up by itself. The push was checked first:
  `origin/main` was `c284616`, with this lane's message and author (lesson 70 is about a ship killed
  from outside that reported exit 4 with nothing pushed). Then the three overlapping docs were put
  aside and merged three ways, and the folder moved with the `read-tree` command `ship` printed.
