## What moved

- **`2bd92e8`, the "Confirm email" review's fixes:**
  - the rollback is described as GoTrue does it: confirmed versus not, the sign-up path refusing inside
    its transaction. This is now in the README's takeover qualifier, the fake's comment, and
    `supabase.ts`'s comment;
  - a first link aged four minutes must still work, which brackets the limit against the six-minute
    refusal;

  - GoTrue's 60 s message is pinned;
  - a stack setting GoTrue never reads is dropped;
  - "Try again" live and the hourly email cap are back under "Not exercised";
  - step 4 says the cap may not bind while "Confirm email" is off.
- **"Try again", run live.** "Try again" is offered when the link's exchange fails for a transient
  reason, with the code kept. Checked against GoTrue's source, it told three cases wrongly:
  - **A lost answer.** GoTrue had finished the exchange and destroyed the code in the same transaction
    (`token.go`), so the retry gets 404. The page said the link "has expired, was already used, or was
    opened in a different browser". Now a retry's 404 says an earlier try may have reached the server
    and used up the link.
  - **A late retry.** A magic link's code lasts five minutes from the link's opening (`flow_state.go`),
    so a retry pressed later gets 422. The page told it as a slow first link ("open it straight away"),
    though the opening was on time. Now it says five minutes have passed.
  - **An answer cut off after its headers.** The browser's own error escaped as the message. A 200 means
    GoTrue committed, so the code is used. This is now final, and the page says the link was used up.

  The live run's gateway can now drop a response, or cut one off after its headers. Its one-shots match
  by path and query, so arming the code exchange cannot take a token renewal, and each step checks its
  one-shot was used. The run moves a code's issue time back in `auth.flow_state` rather than wait.
- **Three reviews of the batch:**

  - **The second, of those fixes** (13 findings), found:

  - **The third** (10 findings, 8 confirmed) found:

    - no check for the case the "Finish the earlier sign-in" label was written for;
    - another tab's request breaking "Try again": the retry paired this tab's code with the browser's
