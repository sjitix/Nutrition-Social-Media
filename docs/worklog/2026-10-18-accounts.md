## What got in the way

- **No Docker and no sudo on this laptop**, so no `supabase start`. Every piece is a user-level binary
  instead: Postgres from a portable build on Maven Central, GoTrue and PostgREST from their own releases,
  and a Node for WSL. The portable Postgres has no `psql`, so SQL goes through the `pg` client
  (`db.mjs`), installed into the same cache.
- **Windows-to-WSL plumbing.** Git Bash rewrote `/mnt/c/…` paths (`MSYS_NO_PATHCONV=1` stops it), and
  quoting did not survive the trip through `wsl.exe`, so WSL commands live in script files. The `.sh`
  files reach bash on stdin with their CRs stripped: a Windows checkout can give them CRLF endings.
- **A stopped stack killed the next one.** Stopping a stack from outside ended its `wait`, and its exit
  handler then ran `down` again, by then against the next stack's servers through the shared PID files.
  Each stack now stamps an owner id and tears down only what it still owns.
- **A mutation filter that proved nothing.** The quick check first suggested for the move,
  `--only "WRITE FENCE|savedStore"`, selected 1 of the 21 guards in the moving files: mutations are
  named for the behaviour they break, not for their file. Checking the filter against the runner's
  real list caught it before anyone relied on it, and v1 ran the full 85 instead.
- **`ship.mjs` would not push a new folder.** It compares `git status`'s `?? scripts/account-live/`
  with the commit's list of files, which can never match. Its commit was checked by hand (15 files,
  byte for byte) and pushed. v1 is fixing the check; until then, name a new folder's files one by one.
- **A line-ending "conflict".** Merging the shared docs over the models lane's commit showed every
  line as conflicting: the working copies are CRLF and git's blobs LF. With the CRs stripped first,
  both merged cleanly.
- **A size control that was not a control.** The first control build ran in a throwaway worktree whose
  `node_modules` was a junction to this one's. webpack then saw every package under a different path,
  so the chunks were split differently, and the split appeared to cost +1 kB on every app page. Built
  in the same folder as the split, the control shows no such cost. Two lessons:
  - Build both sides of a size comparison in one folder with one `node_modules`.
  - Next's printed First Load JS cannot be the measure here. It left out the control's storage chunk,
    so it showed the split as 1 kB *bigger*. Count the gzipped size of every file the route loads
    instead.
