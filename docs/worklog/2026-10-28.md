# 2026-10-28 — D7: what you logged stays logged, and Today counts it

**Milestone:** V1 D7 (B1, meal logging end to end, with records surviving every re-plan).
**Solved:** yes. The engine half is `e25aa20` (test:engine 1283/0) and the UI half `39e71b5`. F8 is still waiting on
the owner, so D7 came first, as the 10-27 shutdown note said it would.

## What moved

- **No re-plan removes a logged meal, a reservation or an import any more (`e25aa20`).** Reproduced first on main:
  - The setup: one week holding a logged library dish, a logged free-text meal, a reservation and an import.
  - The re-plans: a boost, a cuisine, a fiber push, a fridge clear-out, a new week, a switch to meal-prep, a day
    re-planned and a new calorie target.
  - The result: 27 of 27 re-plans (3 seeds) lost at least one record, with nothing said.

  The two causes, both recorded on 10-21:
  - selection from scratch never had the records, and nothing put them back;
  - a logged library dish looked like a planned one (review #18).

  The fix:
  - A meal now carries `record: "logged" | "out"`, and the engine holds a record fixed everywhere.
  - Every rebuild puts the records back after the pins (`reimposeRecords`), with each import that breaks no new rule.
  - The day is then re-solved around them, except in meal-prep mode.

  The probe now loses 0 of 27. 27 new rows; 17 of them fail on the parent.
- **A stated calorie figure wins over a library match.** "Burger and chips, 900 kcal" was logged as the library's
  Cheeseburger & Fries at 769. It is now scaled to the 900, unclamped, because it is a fact.
- **Today counts the meals you logged (`39e71b5`).** Once anything on the day is logged, the rings are the log. A day
  with nothing logged falls back to the clock and says so on the page: "Nothing logged today, so counted by the clock".
- **"I ate this" on every meal sheet** logs the planned dish at its planned portion, and an import as itself. The Week
  board labels the tile "Eaten", or "Out" for a reservation.

## What got in the way

  five. Running the full engine suite at the same time slowed both.
- **`test:api` failed one row against this machine's `.env.local`.** The row is "a demo reply never claims the plan
  changed", and it got `true`. The file points the assistant at NVIDIA's hosted model, and a live model really does
  change the plan for "make tuesday vegetarian", so the row only holds in demo mode. With `AI_PROVIDER=demo` set on
  the server it passes: 78/0.

## Deferred

- **The accounts lane's `validate.ts` does not check `record` yet**, so a file or an account row with a bad value
  passes. Asked in the lane file: `record` is undefined, "logged" or "out".
- **A record restored over a meal-prep serving** leaves the batch's placement pointing at that slot, as `log_meal`
  already did. The cook still happens, and the grocery list still counts it. → with the meal-prep review.
- **The two 'I ate this' rows were not run against the parent.**
- **F8** → still waiting on the owner (push from the laptop, or rebuild here).
